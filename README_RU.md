# Talend Job Tools для IntelliJ IDEA

[English version](README.md)

Редактируйте Jobs из **Talend Studio 8** в **IntelliJ IDEA 2026.3** (сборка 263.7307 или новее в ветке 263). Плагин правит исходники Talend, а не сгенерированный Java-код.

Плагин показывает Jobs, Routines, Repository Contexts и статические связи `tRunJob`. Штатная Java-навигация и автодополнение IDEA работают между рутинами и в поддерживаемых фрагментах Jobs. Чтобы IDEA видела классы Talend и другие зависимости рутин, [импортируйте их из локального кеша Studio](#импорт-зависимостей-рутин-из-studio).

## Сборка и установка

Скачайте ZIP из [GitHub Releases](https://github.com/atrevido/idea-talend-job-tools/releases) или соберите его из корня репозитория. Для сборки нужны JDK 25 и IDEA 2026.3 с плагинами Java и XML. На macOS можно использовать JBR из IDEA:

```sh
export IDEA_HOME="$HOME/Applications/IntelliJ IDEA.app"
export JAVA_HOME="$IDEA_HOME/Contents/jbr/Contents/Home"
./gradlew check buildPlugin
```

Для установки или обновления в IDEA откройте **Settings → Plugins → ⚙ → Install Plugin from Disk**. Выберите скачанный ZIP или `build/distributions/talend-idea-plugin-<версия>.zip`. Перезапустите IDEA, если она попросит.

## Работа с проектом Talend

1. Откройте каталог с `talend.project` или его непосредственный родитель. Укажите в настройках IDEA тот же Project SDK, который используется для Jobs.
2. Двойным кликом в окне **Talend** можно открыть Job, Routine или Repository Context. Для статического `tRunJob` плагин открывает указанную версию или последнюю, если версия не задана и цель однозначна. После изменения структуры проекта нажмите **Refresh**.
3. В `.item` выберите **Tools → Edit Talend Java…** или одноимённый пункт контекстного меню. Фрагмент откроется в обычной вкладке IDEA с Java-подсказками, навигацией и форматированием.
4. Нажмите **Apply to Job**, затем **Save All**. Закрытие последней вкладки без применения отбрасывает черновик. Плагин меняет только выбранный XML-атрибут и отклоняет запись, если Job изменился или в файле смешаны типы переносов строк. Не редактируйте тот же Job одновременно в Studio: она может перезаписать правку своей старой копией.

При открытии проекта IDEA индексирует исходные Java-файлы Routine `.item` в `code/routines`. Папки Talend служат для группировки; Java-связи определяются объявлениями пакетов. Дождитесь окончания индексации перед автодополнением, переходом к объявлению или поиском использований. **Find Usages** для Routine также находит вызовы в поддерживаемых Java-фрагментах неоткрытых Jobs. Результаты ведут к исходному XML-атрибуту и не участвуют в переименовании.

Поддерживаются `tJava`, `tJavaRow` и существующие выражения и фильтры стандартного `tMap`, в том числе пустые. Подсказки используют поля контекста, схемы строк и Routines текущего репозитория Talend. Для внешних классов настройте зависимости в IDEA. Поле `IMPORT` редактируется как текст, чтобы IDEA не удалила импорты, используемые в другом XML-атрибуте.

Фрагменты не являются самостоятельными Java-классами. Рефакторинги, требующие изменить сгенерированные классы или схемы, не поддерживаются. Плагин не меняет граф, не генерирует, не компилирует и не запускает Jobs.

### Импорт зависимостей рутин из Studio

JDK проекта и библиотеки Studio отвечают за разные части Java classpath. Например, `java.util.HexFormat` входит в JDK 17, а Log4j и системные рутины Talend приходят из Maven-зависимостей рутин.

1. В Talend Studio сгенерируйте Maven POM и убедитесь, что зависимости рутин проекта есть в локальном кеше Studio. Импорт читает `poms/code/routines/pom.xml` и его родительский `poms/pom.xml`, если он указан.
2. В IDEA проверьте, что модуль с `code/routines` использует версию Java из сгенерированного POM. Если модуль наследует SDK, проверьте Project SDK. SDK из диалога импорта используется только для запуска Maven и не меняет настройки проекта или модуля.
3. В доверенном проекте IDEA откройте **Tools → Import Talend Routine Classpath…**. Выберите исполняемый файл Apache Maven из доверенной установки и локальный Maven-репозиторий Studio. Для стандартной установки Talend Studio 8 на macOS путь к нему — `/Applications/TalendStudio-8/studio/configuration/.m2/repository`.
4. Когда импорт покажет число подключённых JAR, дождитесь окончания индексации. Откройте `.item` рутины и вызовите **Go to Declaration** (`⌘B` на macOS) на классе из импортированной библиотеки, например на `LogManager`, если проект использует Log4j.

Импорт запускает Maven Dependency Plugin 3.9.0 **без доступа к сети** и подключает зависимости времени компиляции к модулю IDEA с исходниками рутин. Если Maven не находит артефакт или плагин, заполните выбранный кеш через Studio или обычными средствами Maven и повторите импорт. После изменения зависимостей рутин запустите импорт заново.

Импорт не подключает все JAR из кеша, не скачивает артефакты и не собирает Jobs. Зависимости отдельных Jobs и Java-переменные, которые генерирует Studio, он не добавляет.

## CI и релизы

Сначала запустите `./gradlew check buildPlugin`. Перед ручной проверкой в IDEA согласуйте с пользователем сценарий и экземпляр IDE, в котором будете проверять.

Pull requests запускают тесты JUnit и сборку ZIP на закреплённой версии SDK IDEA. ZIP и отчёты при падении тестов доступны в артефактах Actions. Тесты используют синтетические Jobs; отдельный проект Talend не нужен.

Чтобы выпустить релиз, обновите `version.txt` и влейте изменение в `main`. Workflow **Release** запускает те же проверки и публикует GitHub Release `v<версия>` с проверенным ZIP, `SHA256SUMS` и `BUILD_INFO.txt`. Пуши с уже выпущенной версией проходят проверки, но не меняют релиз. Если запуск завершился ошибкой, перезапустите его: публикацию черновика можно продолжить только с того же коммита. Gradle берёт из `version.txt` версию дескриптора и архива.
